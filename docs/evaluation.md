# Trade-Council 评估与回归基线

## 1. 测试原则

- 单元与回归测试不依赖生产数据和真实模型 API。
- 黄金样例使用固定合成行情，测试结构、时点、证据和数值容差。
- 不比较自然语言全文。
- 未积累足量真实模型重复样本前，不设置任意的决策一致率阈值。

## 2. 黄金样例

基线文件：`tests/golden_baseline.json`

| ID | 代码 | 风格 | 目的 |
|---|---|---|---|
| blue-chip | 600519.SH | 大盘蓝筹 | 稳定趋势与完整数据包 |
| high-volatility-growth | 300750.SZ | 高波动成长 | 波动率与指标稳定性 |
| cyclical | 601857.SH | 强周期 | 周期波动和结构一致性 |

每个样例检查：

- 数据包必需文件存在。
- `snapshot_id` 写入 manifest 和 evidence。
- 行情不包含 as-of 之后的数据。
- Evidence 的 `available_at` 不超过基准日截止时间。
- 相同源文件重复构建得到相同快照和证据轨迹。

## 3. 故障注入

当前覆盖：

- 缺失日线目录。
- 坏 Parquet 文件。
- 行情关键列整列为空。
- 缺失复权因子。
- 非交易日回退到前一交易日。
- 财务公告日晚于 as-of。
- 两融 T+1 发布滞后。

预期：

- 无可用行情时返回明确 `SystemExit`。
- 关键列异常时拒绝生成数据包。
- 缺少复权因子时显式降级为未复权价格，并在 manifest 标记 `ERROR`。
- 非交易日自动回退，manifest 记录实际基准日。

## 4. 报告门禁

变异测试至少覆盖：

- 清空图表数据点。
- 篡改核心决策字段。
- 篡改 Evidence 数字但保留来源标签。
- 删除核心分析域或辩论章节。
- 数据缺口标记数量不一致。
- Evidence 数字缺少来源。

当前 R9 会校验：

- 带 `data-evidence-id` 的数字必须存在。
- HTML 中数字必须与 `evidence.json` 数值一致。
- `action`、`confidence`、`risk_level` 必须与 `decision.json` 一致。

## 5. 重复性与决策一致率

Mock 工作流重复 10 次：

- Schema 通过率基线：`100%`。
- 该指标验证流程稳定性，不代表真实模型分析质量。

真实模型决策一致率状态：`not_established`。

建立方法：

1. 固定数据快照、Prompt 哈希、模型 digest 和参数。
2. 对同一股票至少重复 20 次。
3. 记录决策方向、风险等级、关键论点和证据集。
4. 先形成观察基线，再决定是否设置回归阈值。

## 6. 当前已知问题

- JSON Schema 只实现常用子集，复杂组合关键字尚未支持。
- 子进程隔离不是 OS 级安全沙箱，只适合可信本地方法。
- Prompt-only 方法仍依赖模型自述，缺少独立代码验证。
- 真实模型的重复运行样本不足，决策一致率尚无阈值。
- HTML 审计基于受控模板和正则，不是通用浏览器 DOM 审计器。
- 黄金样例为合成数据，只验证结构与时点，不评价投资收益。

## 7. Phase 9 真实试运行记录

本节中的本地 qwen2.5 运行属于 **batch 分支验证**，用于验证离线链路、
Schema 和安全降级，不作为 v1.0 主线分析质量的主要证据。

2026-10-22 完成 5 只股票的 data/quick 试运行和 600487.SH 的本地完整分析：

| 代码 | 风格 | Quick 方向 |
|---|---|---|
| 600519.SH | 大盘蓝筹 | neutral |
| 300750.SZ | 高波动成长 | negative |
| 601857.SH | 强周期 | positive |
| 000001.SZ | 银行金融 | neutral |
| 600487.SH | 事件/成长对照 | negative |

600487.SH 完整 batch 分析：

- 11 次模型调用。
- 186,371 tokens。
- 约 9.5 分钟。
- 模型原动作 SELL，被 batch profile 安全降级为 `INSUFFICIENT_DATA`。
- 交易参数全部清空。
- 报告审计 PASS，评分 100。
- 主要数据缺口：本地业绩预告最新记录距基准日 97 天。

本次试运行发现并修复：

- 模型可能把“龙虎榜”事实引用到两融证据。
- 模型可能自报错误的能力位。
- batch 模型可能越过 profile 输出 SELL。
- 失败续跑曾把累计成本重置为 0。

上述问题均已加入确定性门禁或回归测试。

### DeepSeek deep 主线样本

同一 600487.SH 快照使用 `deep` profile、`auto` 路由完成：

- 24 次调用，包含证据门禁和不可解析 JSON 的重试。
- 421,144 tokens。
- 最终动作 HOLD。
- 报告审计 PASS，100 分。
- 主要结论：估值分位高、现金流质量弱、中期资金流出、技术趋势未反转。
- 成本因 DeepSeek 单价未配置而明确显示为未知。

这证明主线能够在证据门禁触发后通过带反馈重试完成，而不是放宽门禁。
